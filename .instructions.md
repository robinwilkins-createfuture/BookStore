# Copilot Instructions for BookStore API

## Project Overview
This is a .NET 9 distributed web API using Aspire for orchestration. The project includes:
- **BookStore.Api**: Main ASP.NET Core web API
- **BookStore.AppHost**: Aspire host for running the distributed stack
- **BookStore.ServiceDefaults**: Shared service configurations
- **BookStore.Api.Tests**: Unit and integration tests

## Setup & Build Commands

### Prerequisites
- .NET 9 SDK required
- Docker Desktop (or another container runtime) required for PostgreSQL when running with Aspire
- (Optional) Install Aspire templates (only needed to scaffold new projects): `dotnet new install Aspire.ProjectTemplates::9.5.0`

### Running the Application
```bash
# Start the full distributed stack
dotnet run --project src/BookStore.AppHost

# Run just the API
dotnet run --project src/BookStore.Api
```

### Building & Testing
```bash
# Build the solution
dotnet build BookStore.sln

# Run tests
dotnet test tests/BookStore.Api.Tests/BookStore.Api.Tests.csproj

# Clean build
dotnet clean && dotnet build
```

## Coding Standards & Patterns

### C# Style Guide
- Use **PascalCase** for class names, methods, and public properties
- Use **camelCase** for local variables and private fields
- Use **UPPER_SNAKE_CASE** for constants
- Prefix private fields with underscore: `_fieldName`
- Use `var` keyword when the type is obvious from context
- Prefer expression-bodied members for simple properties

### Architecture & Project Structure
- **Controllers**: HTTP endpoint handlers
- **Services**: Business logic and calculations (IBookService, BookService)
- **Dtos**: Data Transfer Objects for API responses
- **Models**: Domain models (e.g., Book entity)
- **Data**: Database context, migrations, and initialization
- **Configuration**: Settings and database configuration

### Async/Await Patterns
- Use `async`/`await` for all I/O operations (database, HTTP calls)
- Return `Task` or `Task<T>` from async methods
- Use `ConfigureAwait(false)` in library code
- Avoid `async void` except for event handlers
- Prefer `await` over `.Result` to prevent deadlocks

### Dependency Injection
- Register services in `Program.cs` using the DI container
- Use constructor injection for dependencies
- Leverage the built-in `IServiceProvider` and `IServiceCollection`
- Configure Aspire-managed services in `BookStore.ServiceDefaults`

### Entity Framework & Database
- Use Entity Framework Core for data access
- Use migrations for schema changes: `dotnet ef migrations add MigrationName`
- Register the DbContext via DI (e.g., `AddDbContext`) and let the DI scope handle disposal (no manual `IDisposable` implementation needed)
- Seed data through `DatabaseInitializer`

### Testing
- Write unit tests for business logic (Services)
- Write integration tests for Controllers
- Use descriptive test names: `MethodName_Scenario_ExpectedResult`
- Mock external dependencies in unit tests
- Place tests in `tests/` directory mirroring source structure

### Documentation
- Include XML documentation comments on public APIs
- Use `///` for method and class documentation
- Document parameters, return values, and exceptions
- Keep README.md updated with setup and running instructions

## API Conventions
- Use RESTful endpoints (`GET /api/books`, `POST /api/books`, etc.)
- Return appropriate HTTP status codes (200, 201, 400, 404, 500)
- Use DTOs for API responses (not domain entities directly)
- Implement consistent error handling and response formats
- Use `[ApiController]` and route attributes in controllers

## Version Control
- Use feature branches for new work: `feature/feature-name`
- Keep commits atomic and descriptive
- Run tests before pushing code
- Keep `main` and `develop` branches stable

## Common Tasks

### Adding a New API Endpoint
1. Create a DTO in `src/BookStore.Api/Dtos/`
2. Add the endpoint logic in `src/BookStore.Api/Controllers/`
3. Implement business logic in `src/BookStore.Api/Services/`
4. Add corresponding tests in `tests/BookStore.Api.Tests/`
5. Document the endpoint in `src/BookStore.Api/book-store-api.http`

### Adding Database Functionality
1. Update the entity in `src/BookStore.Api/Models/`
2. Create a migration: `dotnet ef migrations add YourMigration --project src/BookStore.Api`
3. Update the DbContext in `src/BookStore.Api/Data/BookStoreDbContext.cs`
4. Update seed data if applicable in `src/BookStore.Api/Data/Seed/`
5. Test with the database
